# E93.004 - Optional infrastructure ledger

## 1. Logical classification

The direct closure theorem separates theorem obligations from optional proof
architectures.

```text
minimal sufficient theorem:
  DIRECT-BORDERED-ANCHOR;

optional iterated-limit infrastructure:
  fixed-L projective convergence;
  GAP-Z or VITALI-Z;
  the cofinal diagonal;

optional Weyl construction:
  LP;
  BTG-DIV;
  mu-free completeness;

optional tail construction:
  RDP-SHELL;
  directional PROLATE and WEIL-TAIL control;

optional endpoint coordinates:
  parity Feshbach scales;
  Kato current;
  Euler line coboundary.                              (1.1)
```

## 2. What optional means

An optional module may still be useful for proving the direct anchor.  It is
not a logically independent condition that must be closed before `Omega7`.
Failure to prove one optional module does not obstruct a proof using another
coordinate.

In particular,

```text
GAP-Z is sufficient for one iterated convergence route;
GAP-Z is not necessary for the direct route;
GAP-Z cannot supply the arithmetic identification by itself.          (2.1)
```

This verifies the build-neutrality diagnosis: a convergence theorem valid for
both the zeta and planted constructions cannot be the force-bearing
arithmetic separation.

## 3. Remaining open count

In the minimal direct architecture there is exactly one open theorem:

```text
DIRECT-BORDERED-ANCHOR.                               (3.1)
```

It contains both convergence and identification because they are not split by
an iterated limit.  Its single status must not be read as a small gap: by
E93.002 it is equivalent in force to `Omega7`.
